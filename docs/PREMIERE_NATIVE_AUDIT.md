# Native Premiere control audit

Audited 4 November 2026 against `main` at `c7a5702`, Adobe's UXP reference and Adobe's own declarations/sample code linked below. This audit adds a read-only host inventory, not effects, transitions or tracking implementation. No installed Premiere instance is available in the development environment; actual editing remains unverified.

## Product contract

The primary product is an instruction-driven panel inside Premiere Pro. Local AI interprets requests and suggests footage; the plugin applies validated operations through Premiere's own APIs. Individual clips, native effects, transitions and keyframes should remain editable in Premiere. The standalone renderer remains optional. Do not substitute baked cropped clips, external rendered effects, guessed menu commands, undocumented QE calls or external tracking for requested native operations.

Adobe exposing a method, our adapter implementing it, and the operation working in an installed host are three different evidence levels. Presence checks alone establish only the first. Unsupported requests must continue to block automatic creation with an explanation.

## Capability map

| Requested capability | Evidence / native route | Current plugin and manual step |
| --- | --- | --- |
| New editable sequence, individual clips, music excerpt | `Project.createSequence`, `ClipProjectItem.createSubClipAction`, `SequenceEditor.createOverwriteItemAction`, undoable transactions | Existing experimental adapter; automated contract tests only. Premiere 26.3+ required for subclips. Real host acceptance pending. |
| Trim, move, reorder or remove timeline items | `VideoClipTrackItem`/`AudioClipTrackItem` in/out, start/end and move actions; `SequenceEditor` insert/remove/clone actions | APIs documented; command handling, stable targeting and preservation of manual edits not implemented. Adjust in Premiere for now. |
| Vertical 9:16 / square sequence dimensions | `SequenceSettings.setVideoFrameRect`, pixel aspect and sequence settings action | APIs documented; output controls not implemented. Changing dimensions alone does not follow a subject. Set dimensions manually for now. |
| Native Auto Reframe | Adobe's CEP sample invokes ExtendScript `Sequence.autoReframeSequence(numerator, denominator, motionPreset, newName, useNestedSeqs)` and receives a new sequence | No equivalent command found in the audited UXP Sequence/SequenceEditor declarations. No ExtendScript bridge is shipped. Use **Sequence > Auto Reframe Sequence** manually. Bridge feasibility and installed-version compatibility need a separate proof. This is a gap in our current integration, not a claim that Premiere cannot automate it. |
| Subject / mask tracking, choose which performer to follow | No dedicated subject/mask-tracking control found in audited UXP declarations | Manual tracking and correction. Finding an Auto Reframe effect in an effect catalog does not establish access to its Analyze action or target selection. No reliable identity-following claim. |
| Native video effects | `VideoFilterFactory.getMatchNames/createComponent`, `VideoComponentChain.createAppendComponentAction`, `Component.getParam`, parameter value actions | APIs documented; typed actions and parameter mappings not implemented. Apply/configure effects manually. Enumerate installed match names instead of assuming every effect exists. Third-party effects may differ. |
| Native video transitions | `TransitionFactory.getVideoTransitionMatchNames/createVideoTransition`, `VideoClipTrackItem.createAddVideoTransitionAction`, `AddTransitionOptions` | APIs documented; selection, duration/alignment, source handles and command implementation pending. Add transitions manually. Factory enumeration is not a successful transition test. |
| Position, scale, opacity and parameter animation | `ComponentParam.createKeyframe`, `createSetValueAction`, time-varying/add-keyframe/interpolation actions; `PointF` where required | APIs documented; specific parameter types, coordinate systems, timing and write/readback behavior need validation. Use Effect Controls manually. Keyframe support varies by parameter. |
| Slow motion, speed ramps, reverse | UXP exposes `getSpeed` and `isSpeedReversed`; no direct speed-setting or time-remapping command found in the audited declarations | Still unsupported by our plugin. Use **Speed/Duration** or **Time Remapping** manually. Source frame-rate interpretation is not equivalent to an isolated timeline retime and can affect other uses of the source. Generic keyframe access is not proof of speed-ramp control. |
| Colour grading / Lumetri / LUTs | Video effect and component-parameter route; `ClipProjectItem.createSetInputLUTIDAction` accepts a LUT ID | Candidate route, not complete Lumetri-panel control. Parameter discovery, LUT registration/IDs, colour space and target scope need validation. Grade manually. Do not change shared source LUTs as an implicit clip-only edit. |
| Editable titles / lower thirds | `SequenceEditor.insertMogrtFromPath/insertMogrtFromLibrary`, exposed component parameters | MOGRT insertion documented. Template-specific editable controls and text support vary. Typed `MogrtText` reference is marked **27.0**, beyond our 26.3 baseline; do not assume it exists on all installs. Native title command not implemented; use Premiere Graphics manually. |
| Audio volume, fades, effects, music ducking | Audio clip component chains and parameter/keyframe actions | Candidate route; gain units, level mapping, keyframe timing and ducking logic not implemented. The current adapter places a music excerpt; it omits original video sound. Mix and add speech manually. No dedicated automatic-ducking command was established by this audit. |
| Transcript / speech selections / captions | `Transcript.transcribeClipProjectItem`, transcript JSON import/export and language-pack discovery | APIs documented; speech editing not implemented. Transcription can need a language pack. Transcript access does not prove caption-track generation; use Premiere Text/Captions manually. No transcription or pack download occurs during the inventory. |
| Native export | `EncoderManager.getManager().exportSequence`, AME queue/launch APIs | APIs documented; preset/output selection and completion/error handling not implemented. Use Premiere Export manually. A successful queue request alone would not prove the output file completed. |

“Not found” refers to the specific public UXP material audited here; it does not establish that a future API, a different scripting interface or a C++ integration is impossible. Adobe's transition guidance retains CEP temporarily, but a legacy bridge adds packaging, security and version testing. It is not an implemented feature of the current CCX.

## Check on the home PC

1. Load the updated development panel with UXP Developer Tool. The previously downloaded 0.4.0 installer does not include this new check; a subsequent successful Windows build packages it.
2. Open a small test project with a sequence containing at least one video clip and one audio clip. Existing client projects are not needed for this read-only check.
3. In the panel choose **Native Premiere tools > Check native tools**. The local AI helper does not need to be connected.
4. Choose **Save tool report** to save the inventory locally. It records API presence, installed video-effect/transition match names, and bounded clip/component/parameter method samples. It does not include footage paths, pairing tokens, transcript text or parameter values. It makes no external requests.
5. An unavailable/read-error result is not proof that Premiere lacks the feature. Open the relevant sequence/clips, retry and review the installed version. Empty catalogs are reported as empty; they are not successful editing tests.

The inspector calls getters and enumerators only. It does not create Action objects, instantiate effects, mutate selections/settings, start analysis/transcription/export, save the project or download anything. Its samples cover only the first found clip per media type within 16 tracks, up to 16 components/32 parameters each. A project switch during the check or an unreadable getter can leave a partial report with errors. No whole-project compatibility guarantee follows from this report.

## Next implementation and acceptance gates

1. Run the existing new-sequence adapter in installed Premiere. Check every source range, timeline start, frame rate, music offset, duration, original project/source preservation and partial-failure behavior. Confirm original clip audio expectations explicitly.
2. Implement a narrow native effects/transition vocabulary first, using installed match names and typed parameter mappings. Apply to a new or explicitly targeted sequence, verify resulting components/values/timing and Undo, then validate visually. Cross Dissolve with sufficient handles and a simple opacity/scale change are practical first tests.
3. Prove Auto Reframe through a supported native route on the installed version. Verify a distinct 9:16 sequence, editable source clips/effects, completed analysis and unchanged original. Test single performer, crossing dancers, group performance and no-subject footage. Keep the manual step explicit until this passes.
4. Add native title/audio actions with template/parameter tests. Treat retiming, masks and automatic captions as separate integration investigations; do not invent success from a model-generated plan.
